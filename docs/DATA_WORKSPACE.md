# 数据接入与质量工作台

本地工作台提供资料上传、原文保存、分块检索、规则质检、清洗预览与版本更新。它面向本地单工作区，不等同于团队服务 `/v1` 的数据权限与 PDF 处理流程。

## 接入与检查

- 支持 UTF-8 的 Markdown、TXT、CSV、JSON，以及 DOCX 正文；JSON 和 CSV 会先进行格式检查。每个文件上限为 2 MiB，正文上限为 500,000 字符。
- CSV 和 JSON 在工作台中作为原文资料保存与检索，不代表已建立表格字段映射、增量同步或结构化数仓。
- 资料区可针对当前版本运行规则检查，包括短正文、异常字符、重复行、CSV 表头和字段数异常，以及 JSON 对象内的重复键。JSON 重复键提示只给出次数，不展示字段名或字段值；问题与统计来自当前文档，并非真实准确性或合规性的自动证明。

## 安全清洗和版本

清洗只预览换行、行尾空格和连续空行的规范化，不自动替换事实。使用者须先查看前后文本，再决定是否应用。应用后创建文档新版本，旧版本留存；依赖旧资料的 Wiki 会按原有逻辑标记为失效。若文档在预览后发生更新，操作返回冲突并要求重新预览。

CSV、JSON 的空白可能属于结构化字段值，本工作台不对这两类来源提供自动清洗。其他文档的空白也可能有排版含义，应先对照预览。

## 当前边界

规则检查不使用大模型，不自动识别事实错误、敏感信息或版权问题；尚无批量任务调度、质量规则配置、人工审核流和多源增量同步。团队模式的权限与发布流程不因本地工作台新功能而改变。

CSV 解析仍受 Python 运行时的单字段长度上限约束，默认常见值为 131,072 字符；即使文件总大小未超限，较长字段也可能被拒绝。能够识别的超限会返回字段长度提示或 `csv_field_too_large`，不输出字段内容；无法识别的解析异常采用通用提示。系统不会为单次请求修改进程级上限。
