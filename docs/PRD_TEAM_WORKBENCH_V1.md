# 知证团队知识工作台产品需求文档

版本 1.1　编写日期 2026 年 11 月 12 日

本版目标是把现有知证团队服务变成业务人员可以使用的网页产品，打通资料接入、持久任务、校订复核、条件发布和证据使用。交付对象为单工作区、单机部署的内部团队。企业级要求在本版具体体现为权限、状态一致性、可恢复流程、可追溯证据和可验证交付，不据此承诺多机高可用或任意规模的服务能力。

## 1 产品目标与事实边界

### 1.1 用户问题

资料维护人员需要更新知识，但不应靠手工调用 HTTP API 完成每次导入与发布。复核人员需要看到原文、质量提示和版本条件，避免误把尚未审核的修订开放给使用者。员工和 Agent 需要知道证据来自哪份资料、哪一版，资料更新之后能发现引用失效。

### 1.2 基线事实

核查基线为 bc912b69f48b6827a1522302dcaf765e1c5ec63a。现有代码包含 FastAPI、SQLite WAL、独立导入 worker、用户会话、知识库角色、受限令牌、持久任务、人工校订、复核、条件发布、BM25、证据回读与引用校验。团队网页只有基础登录和检索。原本地工作台与团队服务具有不同数据目录和权限边界。

现有代码与测试的存在，不等于目标服务器已完成部署验收。当前没有确认真实客户、使用人数、生产容量、业务审批制度或 SLA。售后资料只用于虚构演示与隔离验证。

### 1.3 本版成功条件

业务用户从网页完成一次新资料发布和一次版本更新；刷新后能重新找到任务；失败可重试；校订不覆盖他人的新修改；未经复核的资料不进入普通检索；新版发布后旧引用被识别为失效；管理员能管理账号与知识库授权，并定位操作记录和服务状态。

代码完成以本文需求编号、行为测试、真实浏览器调用本地服务及恢复验证为证据。正式上线仍须在目标服务器核实 TLS、进程管理、监控、备份计划、容量和真实用户反馈。

## 2 范围与维护取舍

### 2.1 本版实施范围

保留现有 Python 服务与原生网页技术，新增可维护的团队控制台。后端补充带权限和分页的任务、待审修订、修订历史、用户、授权成员和本人令牌查询。沿用原有导入、校订、复核、发布与取证接口。

不引入新的数据库、前端构建链或队列基础设施。新增索引采用幂等的增量方式，不删除旧表和历史内容，不自动打开现有真实业务数据目录进行迁移或种子写入。

### 2.2 后续范围

多租户计费、单点登录、组织层级、双人强制审批、数据库连接器、结构化数仓、增量同步、多机高可用及新的问答生成链路均不属于本版。现有 Wiki API 和本地 Agent 功能继续保留，不把它们宣称为团队网页已经具有的新功能。

### 2.3 产品维护原则

任务状态、修订状态、当前公开版本和引用快照分别处理。列表以服务端数据为准，授权在服务端执行。页面失败保留必要输入，禁止静默模拟成功。没有外部监控或恢复证据时，页面明确显示未知或待验证。

## 3 用户与权限

| 身份 | 允许的主要任务 | 限制 |
| --- | --- | --- |
| reader | 阅读授权知识库已发布资料，检索、回读和校验本人证据 | 不查看待审内容，不导入、不校订、不复核发布 |
| editor | 在授权库中导入，跟进任务，查看和校订待审资料 | 不能完成复核发布 |
| publisher | 包含编辑能力，执行明确复核和条件发布 | 发布仍需当前版本条件、复核结果与幂等键 |
| 知识库 admin | 在对应库中包含 publisher 能力 | 不等于全局系统管理员 |
| 全局管理员 | 管理用户、知识库、成员授权和审计，处理团队维护 | 不能关闭当前自己的管理账户而导致不可恢复操作 |
| Agent 令牌 | 按本人当前权限、知识库与 scopes 取得证据 | 不进入团队管理写流程，不因持有令牌绕过撤权 |

前端根据服务端返回的角色展示操作和说明，不能只靠按钮隐藏实现授权。每一次查询和写入均重新校验当前权限。角色变化后，旧分页 cursor 必须失效或被当前权限重新约束。

## 4 信息架构与页面规则

### 4.1 公共框架与登录

R01 会话与工作区。登录页只收集用户名、密码；密码不放入 URL、localStorage 或日志。认证后获取本人身份与授权知识库，显示实际角色，不提供模拟角色切换。知识库切换清除当前列表 cursor、修订上下文和未完成检索快照，避免串库。

会话失效后清除页面中的资料与一次性凭证，返回登录提示。所有写请求沿用 CSRF。退出失败不能显示已成功退出。当前服务只支持 default 工作区，其他工作区路径继续拒绝访问。

### 4.2 资料与版本

R02 资料目录。展示标题、稳定来源键、当前公开修订与编号，提供新建来源、更新来源、查看历史修订及当前原文。reader 和 Agent 只看已有公开版本的目录，不能通过目录获取尚未发布的来源名称。editor 及以上可查看待处理来源。

目录提供加载、空列表、错误、分页和刷新状态。更新必须选择明确的文档与当前公开修订。没有公开版的来源应继续跟进既有任务，不伪装成一次公开版本更新。

### 4.3 文件导入

R03 新建与更新。表单字段为知识库、文件、模式、稳定来源键；更新还包含 document_id 和 expected_revision_id。新建使用独立来源键；更新沿用已选资料的来源键。后端仍检查文件名、内容、大小、权限与来源冲突。

文本格式 Markdown、TXT、DOCX、CSV、JSON 上限沿用 2 MiB；PDF 上限读取服务端 capabilities，不由页面另写不一致常量。文件不会由网页上传到第三方。提交中禁用重复操作；网络不确定时同一未变请求保留幂等键，不能自动重复创建。表单变化后生成新的请求身份。

202 表示服务已接收。页面取得 job_id 后进入可分享的任务定位页面；刷新后通过真实 API 查回任务，而非模拟进度。失败保留文件选择和表单，显示错误说明与 request_id，敏感正文不回显到通用错误信息。

### 4.4 导入任务

R04 任务恢复。列表按知识库和状态查询，使用 cursor 分页。字段包括任务 ID、来源、修订、状态、处理页数、尝试次数、更新时间和失败代码。未授权者不能枚举其他库任务；查询权限与单项任务规则一致。

详情定位保存在 URL 的知识库和任务 ID，不保存密码或令牌。活跃任务低频刷新，页面离开或会话失效后停止请求，不允许旧响应覆盖新知识库。完成、失败、取消时停止轮询。错误提示区分网络请求失败和后台任务实际失败。

取消可能先进入 cancel_requested，只有服务端确认后才能显示已取消。失败或已取消的任务可按现有尝试次数限制重试；重试沿用原 job_id。处理成功和发布完成使用原有状态含义，不把 ready 改为仅解析完成。

### 4.5 待审与原文校订

R05 待审队列。按库查询 needs_review 和 awaiting_publish，显示修订、质量摘要、复核状态和关联任务。editor 可进入校订，publisher 可以复核发布。已发布、失败和取消修订不进入待审列表。

R06 校订复核发布。详情展示原始抽取文本、当前校订正文、页码、质量提示、修订状态和当前公开版。多页内容可逐页读取，空页和失败有明确反馈；不一次载入全部大型 PDF 正文。

保存使用当前 text_sha256；412 表示发生并发修改，保留本地正文并让使用者显式重新读取。成功校订撤销原复核，未保存正文不允许继续复核发布。复核说明至少 5 字，publisher 明确操作后记录。

发布前展示将替换的公开版与目标修订，并要求用户确认。新来源使用 If-None-Match: *；更新使用 If-Match 当前公开修订；均携带幂等键。前置条件冲突要求刷新比对，不自动重发覆盖。保留历史修订与原文件，不自动删除。

### 4.6 检索与取证

R07 证据使用。输入问题和当前授权知识库，返回证据片段、来源修订、定位与质量提示。提供原文回读和引用校验；需要完整回读时使用证据与检索凭据，不接受任意文件路径。

无命中显示空状态。来源版本、权限或凭据已失效时保留错误上下文并提供重新检索。校验结果清楚显示 semantic_support 为 not_checked，不把版本校验解释为已经证明模型结论正确。本版不新增模型调用、API Key 输入或自动问答承诺。

### 4.7 用户授权与 Agent 接入

R08 管理与令牌。全局管理员可分页查询用户，创建账户、停用其他账户、创建知识库，查看成员并赋予或撤销库角色。页面不展示密码哈希、会话凭证、CSRF 哈希。停用本人账户应明确拒绝，不能靠前端隐藏规避。

本人可查询所发 Agent 令牌的范围、到期时间与撤销状态，创建受限只读令牌并撤销。新明文只在生成结果中展示一次，提示立即保存；离开该页面或退出后清除，不写入持久浏览器存储。普通列表只返回不可作为 Bearer 使用的 token_id 及元数据。

### 4.8 运维与发布记录

R09 运营与运维。管理员查看服务 live、ready、worker 心跳状态、现有指标及关键操作审计。worker 心跳正常只说明监督进程存活，不能直接显示解析容量或 SLA 合格。审计采用分页，不把所有历史一次加载。

备份和恢复继续采用现有受控 CLI，不在网页暴露任意磁盘路径或一键覆盖恢复。页面及手册提供操作路径与验收清单。备份定时、隔离副本、外部告警、TLS 与正式环境恢复记录属于现场门禁。

## 5 状态与一致性契约

| 对象 | 主要状态 | 规则 |
| --- | --- | --- |
| 导入任务 | queued、parsing、cancel_requested、cancelled、failed、needs_review、awaiting_publish、publishing、ready | job_id 持久；ready 表示发布链路结束 |
| 修订 | staging、needs_review、awaiting_publish、published、archived、failed、cancelled | 校订撤销复核；待审版本不进入默认检索 |
| 资料 | current_revision 可为空或指向公开版 | 新稿处理失败不修改已有公开版 |
| 证据 | 当前有效、来源变化、凭据过期、权限变化、内容不匹配 | 任何失效都不能继续显示为当前有效 |
| 页面请求 | 加载、成功、空、失败、会话失效、取消 | 旧响应不得覆盖新页面与新知识库 |

发布需要同时满足授权、复核、编辑 epoch、当前公开修订和知识库 generation 条件。重试和前置条件的原有服务端逻辑继续保留。前端解释这些规则，不自行决定发布成功。

## 6 数据和接口契约

### 6.1 数据关系

工作区的知识库包含资料；资料具有稳定 source_key 和多个修订；修订包含页面及质量提示；任务关联修订；复核和发布产生审计；取证凭据保存知识库快照与原文证据。用户通过知识库角色获得授权，Agent 令牌叠加 scopes 与库范围。

本版不更改历史正文模型，只增加必要查询索引和接口。个人信息和凭证只在认证管理需要的最小范围处理。资料事实真实性、敏感信息识别和版权判断仍需要业务人工确认。

### 6.2 列表与身份接口

| 接口 | 主要输入 | 返回字段及权限 |
| --- | --- | --- |
| GET /v1/me | 会话 | 本人 ID、用户名、全局管理员标记、身份类型与 scopes |
| GET /v1/workspaces/default/knowledge-bases | 当前身份 | 授权知识库、generation 与实际角色 |
| GET /v1/workspaces/default/documents | knowledge_base_id、cursor、limit | 资料、source_key、公开修订及编号；reader 隐藏无公开版来源 |
| GET /v1/workspaces/default/jobs | knowledge_base_id、status、cursor、limit | 授权任务列表和 next_cursor |
| GET /v1/workspaces/default/review-queue | knowledge_base_id、cursor、limit | 待审修订、质量、复核结果与任务定位 |
| GET /v1/workspaces/default/documents/{id}/revisions | cursor、limit | editor 的修订历史，含状态、当前公开版和分页 |
| GET /v1/users | cursor、limit | 全局管理员可见的账号元数据，不含凭证 |
| GET /v1/workspaces/default/knowledge-bases/{id}/members | cursor、limit | 全局管理员可见的库成员与角色 |
| GET /v1/tokens | cursor、limit | 本人 Agent 令牌元数据，不含明文 |

新增列表 limit 默认为 20，范围 1 至 100。cursor 签名并绑定身份、列表类型、工作区、库、状态、分页大小及当前权限语境，10 分钟过期；每页重新校验授权。排序为稳定 ID 顺序。列表不是冻结快照，分页期间新增或状态变化需要刷新查看，不能承诺动态列表快照一致性。非法或不匹配 cursor 返回 400 INVALID_CURSOR。

### 6.3 沿用的写入与取证

沿用 POST uploads、GET jobs/{id}、POST jobs/{id}:cancel、POST jobs/{id}:retry、GET 修订与页面、PUT 页校订、POST 修订:review、POST 修订:publish，以及 POST retrievals、evidence:read、citations:validate。沿用用户、知识库、成员授权和令牌创建撤销接口，公共响应继续包含 schema_version、request_id 和 elapsed_ms。

写入错误使用已有稳定代码。401 返回登录；403 明确权限或 CSRF 失败；409 表示状态或知识已变化；412 保留输入并重新读取；413 或 422 解释文件或参数问题；429、503、504 提供重试建议。不能无限自动重试写请求。

## 7 安全和体验要求

R10 安全边界。团队页面只调用 /v1；/api 继续禁用。静态资源只按明确文件白名单公开；不能引入任意路径下载。HTML 和脚本同源，内容用文本节点展示，禁止把资料正文直接拼成可执行 HTML。为团队页面设置 CSP、防嵌入、类型嗅探与隐私缓存策略。浏览器不持久化凭证、资料正文和一次性令牌。

R11 响应式与可用性。桌面显示导航和清晰任务区；390 像素宽度可完成主要操作，表格在自身容器滚动，页面整体不横向溢出。输入有可读标签，键盘焦点可见，错误有文字说明，不只使用颜色。耗时操作有状态，按钮不可重复提交，路由切换停止旧请求。发布确认是明确动作，不使用默认勾选。

## 8 实施顺序与验证门禁

第一步冻结本文与需求编号；第二步运行原有全量回归作为基线；第三步实现授权列表与安全元数据；第四步实现真实控制台；第五步补充针对权限、分页、状态和前端契约的行为测试；第六步用真实本地服务和浏览器走通新建、更新、冲突与引用失效；第七步整理运行手册、Word PRD 和交付矩阵。

R12 可复核交付。最终报告逐项列出实现文件和验证方式，不用原型截图冒充后端联调，不用历史离线测试冒充本次成绩。使用隔离数据目录与虚构样例，不读取任何项目 .env 文件，不修改已有真实业务数据。

| 编号 | 本地验收重点 |
| --- | --- |
| R01 | 登录、实际角色、退出及会话失效清理 |
| R02 | 授权目录、隐藏未公开来源、分页与修订历史 |
| R03 | 新建和更新的真实文件上传、幂等与 202 反馈 |
| R04 | 任务列表、刷新恢复、失败重试及取消状态 |
| R05 | 待审列表正确进入退出，授权与 cursor 防绕过 |
| R06 | 多页读取、校订冲突、撤销复核、明确条件发布 |
| R07 | 原文回读、真实引用校验、新版后旧引用失效 |
| R08 | 账号和库管理、成员授权、令牌一次展示及撤销 |
| R09 | 真实健康状态、管理员指标审计、恢复记录 |
| R10 | 静态白名单、安全响应头、凭证无持久存储 |
| R11 | 桌面和手机、键盘标签、错误保留输入 |
| R12 | 原有与新增回归、浏览器实测、文档与代码对应 |

## 9 正式上线前必须补充的业务决定

真实资料维护者和复核者、是否强制双人审批、数据敏感等级、账号保留和停用流程、容量目标、最长等待时间、备份保留期、RPO/RTO 与告警负责人须由实际试点确认。它们不会由代码自动生成。

上线前在目标机器执行 TLS 全链路、反向代理头、受限账户、worker 自动重启、磁盘不足、备份恢复和容量测试。该环境尚未提供，本轮不把这些项目标记为通过。代码可交付和生产验收分别记录，后续以实际证据更新。
