# 团队资料质量与审核

团队服务在用户授权的知识库中处理资料，不开放本地工作台的 `/api/*`。上传由现有持久任务接收，原始文件按内容哈希保存；解析产生的页面、质量提示与修订版本绑定。

## 导入与检查

支持 PDF、Markdown、TXT、DOCX、CSV、JSON。CSV 和 JSON 作为文档正文保留与检索，不提供数据库表、行级权限或增量同步。CSV 检查基础语法、空或重复表头及字段数；JSON 检查严格语法和同一对象中的重复键，包括嵌套对象。重复键提示只包含重复次数，不输出字段名和字段值，也不会修改原文。所有页面检查短正文、编码替换字符、异常控制字符和重复行，PDF 另标记空页、低文本量和缺字。检查只提供可解释的提示，不能证明事实准确或满足合规要求。

通过已有的任务状态 API 查看 `quality_summary`；使用 `GET .../documents/{id}/revisions/{revision}/pages/{page}` 查看某页的 `quality`。待发布修订仍受知识库权限约束。有提示的修订进入 `needs_review`；无提示的修订进入 `awaiting_publish`，两者都需要授权的 publisher 明确审核后才能条件发布。

## 校订和发布

编辑者可校订待审页，须提交当前文本哈希；不匹配返回 412，防止覆盖他人更新。系统保留抽取原文，重新计算该页提示及修订汇总，并撤销之前的审核状态。CSV 或 JSON 校订必须通过格式验证。校订完成后仍需 publisher 复核，复核不是对真实性的自动保证。

已有历史修订不会自动重跑新增规则；新导入或显式校订时使用当前规则。处理版本升级后，旧任务不会仅凭相同内容被复用；需要重新处理已有来源时，应使用更新流程、提供当前修订并使用新的幂等键。同一个幂等键仍会返回原请求的结果，不会触发重检。文件名变化也不会直接复用旧解析任务。规则未覆盖的隐私、版权、敏感信息和业务字段仍需由业务人员检查。

## 运维边界

单机工作区依赖 SQLite 与一个 API 进程，任务解析使用单独 worker。上线前应使用 [部署预检](DEPLOYMENT_PREFLIGHT.md)，并在真实环境验证 TLS、账号与目录权限、备份恢复、容量、监控和故障响应；预检与本地测试都不构成 SLA 承诺。无法安全自动判定可删除的上传文件可使用[只读候选报告](ORPHAN_UPLOAD_REPORT.md)进行人工排查。

CSV 单字段仍受 Python 运行时字段长度上限约束；默认常见值为 131,072 字符。超过时即使总文件未达到上传上限也可能被拒绝。能够识别的超限会在导入任务中显示 `CSV_FIELD_TOO_LARGE`，质检中显示 `csv_field_too_large`，不暴露字段内容；其他解析异常采用通用提示。
